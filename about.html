Hassan Tsuma

I'm a full-stack engineer based in Kenya, currently a Computer Science student. Most of what I actually know about building real software didn't come from coursework — it came from building RentManager, alone, end to end, and running into the problems a tutorial never mentions.

I like problems where correctness matters more than speed of shipping — money, records, anything a business genuinely cannot afford to get wrong. RentManager started as "build a rental app" and turned into a much more interesting problem the moment M-Pesa, Kenyan tax law, and multi-tenant data isolation entered the picture. I didn't back away from that complexity; I read Safaricom's merchant terms, read the Finance Act, and built a tax module that's fail-closed by default because I'd rather under-compute than get a government filing wrong.

I'm not going to tell you I'm an expert across a long list of technologies — I'm not, yet, and a list like that wouldn't be honest. What I can tell you is that I've built one real system deeply enough to know where the actual hard problems live in software like this: not the CRUD screens, but the tenant boundary, the ledger, the idempotency guarantees, the things that are easy to get subtly wrong and expensive to have gotten wrong. I'm building depth by taking on harder versions of that same kind of problem, not by collecting frameworks.

Outside RentManager, I'm still working through the fundamentals properly — data structures, algorithms, the JavaFX exercises on my GitHub are part of that, not polish for a portfolio. I'd rather you judge me on RentManager, because it's the real thing.
