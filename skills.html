02EVIDENCE

The skills, with the evidence attached

Backend engineering

Java 21 My strongest language. RentManager's entire backend — 21 modules — is modern Java: records for value types, sealed hierarchies where the domain has a closed set of cases, and the standard library rather than a framework for everything.
Spring Boot 3 Web, Data JPA, Security, Validation, Actuator and scheduled jobs in a production deployment. I've tuned it to run inside a 512 MB free-tier container without the scheduled payment sweeps failing to start.
Modular-monolith architecture Ports and adapters with explicit module boundaries — and ArchUnit tests that fail the build when one module reaches into another's internals. The boundary is enforced by CI, not by good intentions.
Spring Security · JWT / JWKS Clerk-issued tokens verified against a JWKS endpoint. The single most important decision here: the frontend sends a tenant id on every request and the backend ignores it completely, resolving tenancy from the signed claim instead.
Multi-tenant data isolation Enforced at two layers rather than one, because a single missed where clause in a multi-tenant system is a data breach, not a bug.
Concurrency & idempotency A tenant tapping "pay" twice must not produce two charges. I've built idempotency windows, transactional boundaries around the ledger, and a database-backed outbox — and I know which of those I'd want a second pair of eyes on.

Databases & data modelling

PostgreSQL Schema design, constraints that make invalid states unrepresentable, indexing, and an append-only rent ledger: a row is written once, and a mistake is corrected with a new linked reversal rather than an edit.
Flyway migrations 99 sequential migrations, latest at V104, none edited after it ran against a database. The migration history reads back as the schema's actual history.
JPA / Hibernate Productive with entity mapping, fetch strategies and transaction boundaries. Still building judgement about when to stop fighting the ORM and write the SQL.
Domain modelling The part I enjoy most. Leases, occupancies, ledgers, commissions and payouts each have real-world rules, and getting the model wrong is far more expensive than getting the code wrong.

Frontend

TypeScript Client types are generated from the backend's own OpenAPI contract, so if I change a response shape in Java, the TypeScript build fails before anyone sees a broken screen.
React 19 258 components across four distinct user roles, each with a different view of the same data.
Next.js (App Router) 62 routes: server and client components, route handlers proxying the backend, middleware-level auth, and a deployed production build.
TanStack Query Query keys, invalidation after mutations, and optimistic updates only where rolling back is genuinely safe — which, on anything touching money, is rarely.
Tailwind CSS · design systems A consistent token-driven UI with light and dark themes. This portfolio is hand-written CSS with no framework, which is its own kind of evidence.
Accessibility Keyboard paths, focus states, semantic landmarks and honest alt text are things I build in rather than retrofit. I haven't yet tested a full product with real screen-reader users.

Mobile

React Native · Expo A 44-screen RentManager app built on Expo Router, sharing the same generated API client as the web app. Built and running — not yet published to an app store, which is a distribution step I haven't taken.
Push notifications Chosen deliberately over SMS for most alerts, because SMS costs money per message and push doesn't — a design decision driven by what the product could actually afford.
Offline & secure storage Tokens in the device keystore rather than plain storage, and connectivity detection so the app tells the user it's offline instead of silently failing.

Payments & integrations

M-Pesa Daraja Both directions: STK push to collect rent, and B2C to pay landlords out. Callbacks are the hard part — they arrive late, twice, or out of order, and the ledger has to stay correct through all three.
Clerk authentication JWKS verification, webhook handling for user lifecycle events, and role/organisation mapping shared across the web and mobile clients.
Africa's Talking SMS Sent through a database-backed outbox with a scheduled sweep, so a provider outage delays a message rather than losing it.
Kenyan tax rules (VAT, MRI) I read the Finance Act rather than a blog post, and built the module fail-closed: every gate defaults to off until a human confirms it applies. I'm an engineer, not a tax adviser, and the software says so too.

Testing & quality

JUnit 5 · Mockito 1,588 tests across 261 test classes. They're written money-path first: anything irreversible gets covered before the screen around it does.
Testcontainers Integration tests run against a real PostgreSQL container, because an in-memory database that doesn't enforce the same constraints will happily pass a test that production would reject.
ArchUnit Architecture encoded as tests. If the boundary only exists in a diagram, it has already been violated.
Vitest · RN Testing Library Component and hook coverage on the frontend. Thinner than the backend suite, and I'd rather say that than imply parity.

Infrastructure & delivery

Docker Multi-stage builds producing the image that actually runs in production, plus a Compose setup for local development against real Postgres.
Deploying a real system RentManager is live: API on Render, web on Netlify, Postgres on Neon, with a keep-awake ping and scheduled encrypted backups. I built that stack under a hard constraint — it had to cost nothing — and documented it as a runbook.
Git & CI Daily driver, with GitHub Actions running the build and the scheduled backup job.
Observability at production scale Sentry, health checks and structured logs are in place. What I haven't done is operate a system under real load and real incidents — this is the gap I most want a team to close for me.
Distributed systems Deliberately avoided. A modular monolith with a database outbox was the correct call at this scale, and reaching for a message broker would have bought me a better architecture diagram and a worse system.
